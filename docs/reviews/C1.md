# Review — `C1`, build the harness

**Reviewer:** `.claude/agents/adversarial-reviewer.md`, fresh context, run in-session
2026-09-10 against the working tree on `C1/harness` before any commit.
**Dimensions:** correctness · security · performance · code quality · contract compliance ·
process compliance.

**Outcome: 10 findings — 6 major, 4 minor. All 10 addressed.** Every one carried an
executable trigger the reviewer had run; not one was speculative. The reviewer restored the
tree to the state it found it in and verified the restoration.

**This review paid for itself on finding 1 alone**, which is the reason it is mandatory
rather than advisory: the one behaviour `C1` exists to protect was not protected, and the
plan claimed in writing that it was.

---

## Major

### 1. `FR17`/`D5` was not tested. A hardcoded `233` passed every gate.

`test_limit_is_read_from_the_library_not_from_a_literal` asserted
`payload_limit() == mesh_pb2.Constants.DATA_PAYLOAD_LEN` — **re-deriving its expected value
from the same expression under test.** It caught `M1` only because 233 ≠ 190. Hardcoding the
value the library returns *today* satisfied it, the floor, and the pre-commit; the reviewer
committed that mutation and every gate went green.

This is precisely the anti-pattern `docs/plans/C1.md` quotes and claims to have avoided —
*"an assertion that re-derives its expected value cannot see the path that produces the real
one"* — written into the plan by the same hand that then wrote the assertion.

**Fixed.** `test_limit_is_read_at_call_time_not_baked_in` monkeypatches `budget.mesh_pb2`
with a stub reporting `99`; any literal fails it. `M4` was added to hold that line: it
hardcodes `233`, the likelier defect. **`M4` fails exactly one test — the new one.** Before
the fix it failed none.

### 2. `run`, `count` and the pre-commit measured cached bytecode, not the file on disk.

Both CPython's `__pycache__` and pytest's assertion-rewrite cache validate on *integer-second*
mtime plus size, so a same-second same-size edit is served stale and silently. Three triggers,
all run by the reviewer:

- broken shipped code (`fits()` off by one at the boundary) reported `10 passed`;
- a test edited and reverted within one second reported a failure the tree did not have;
- **with `enable_assertion_pass_hook` removed and a cache warm, `count` printed `38` and
  passed** — while the script's own docstring claimed that configuration reports `0`. Adding
  three real assertions changed nothing; it still printed 38 against a true 41.

The stated protection did not hold. `-p no:cacheprovider` disables a *different* cache and
does nothing here.

**Fixed.** `count_assertions.py` points `sys.pycache_prefix` at a fresh temporary directory
per run and `mutate.py` sets `PYTHONPYCACHEPREFIX` for its subprocess, so every run is cold.
Verified: the hook-removed case now reports `0` and exits 1; the broken-`fits()` case is now
seen. **`mutate.py` was silently exposed to the same bug** — a mutation is by definition a
same-second edit, so a warm cache could have run the original code and scored a mutation
uncaught.

### 3. `mutate.py` scored "caught" on any red suite, never checking the named test.

`apply()` tested only `returncode == 0`; `caught_by` was printed and never verified. Renaming
the named test left `M1` reported as *caught by* a test that no longer existed, with the floor
gate green. This is *"a harness scoring a crash as a kill"* — named in `conventions.md` as one
of the defects this whole discipline exists to catch.

**Fixed.** The suite runs with `-rf`, the `FAILED` node ids are parsed, and a mutation is
caught only when `caught_by` is among them. Anything else reports `MISATTRIBUTED` and names
what failed instead. Verified by renaming the test: `0 of 1 caught`, rc 1.

### 4. `mutate.py` left mutated shipped code on disk under SIGTERM/SIGHUP.

`try/finally` covers exceptions and `KeyboardInterrupt` — the reviewer confirmed Ctrl-C
restores correctly — but the default SIGTERM handler exits without unwinding. A closed
terminal, an IDE stop button or a CI timeout left `return 190` in `src/mesh_client/budget.py`.
The docstring asserted the opposite in as many words.

**Fixed.** A module-level `_PENDING` map plus handlers for SIGTERM, SIGHUP and SIGINT restore
before exiting. Verified by signalling a live run: `mutate: signal 15 — shipped files
restored`, and the file on disk is the original.

### 5. The secret scan waved through this project's flagship credential in its likeliest shapes.

`\bpsk` never matches `MESH_PSK` or `CHANNEL_PSK`, because `_` is a word character. The
mandatory quote excluded `.env` and unquoted YAML. Six real shapes passed, including
**`https://meshtastic.org/e/#...` — the channel-share URL, which *is* the key material and is
how Meshtastic channels are actually exchanged between people.** The Google service-account
half of `RR8` held; the PSK half did not.

The `SELF` exclusion was a second hole: it skipped whole files, so a credential parked in
`.githooks/pre-commit` passed while identical content elsewhere was refused.

**Fixed.** Patterns widened for PSK-with-prefix, unquoted values, the channel URL, Google API
keys, GitHub and Slack tokens. Exclusion is now **per line**, keyed on a
`secret-pattern-definition` marker, so the checker can describe patterns without granting any
file a blanket pass. Verified: all six previously-missed shapes now refused.

### 6. The register recorded none of it.

`## Mutations (M)` still read *"Empty."* while three mutations had been run; `H1`–`H6` read
`not built`; the `Units` row said `awaiting G3` after `G3` was closed. Under `NFR8` and the
convention that *a row is not closed until a mutation has been seen to fail, with the count
recorded*, **the register row is the deliverable, not the code.**

`M2` and `M3` were also allocated *in code*, with no register row and no mention in the plan —
the one-intake-path rule inverted, the code minting the ID.

**Fixed.** `M1`–`M4` now carry rows with their evidence; hook statuses updated; `C1.md` and
the `Units` row corrected. The allocation-order slip is recorded in the Mutations preamble
rather than quietly tidied.

## Minor

### 7. `check_secrets.py` crashed on any staged binary and aborted the scan.

`text=True` decodes strictly, so a staged PNG raised `UnicodeDecodeError` — fail-closed, so
not a security hole, but the repository could never commit a binary asset and everything after
the first binary went unexamined. **Fixed:** decode with `errors="replace"`.

### 8. `check_commit_msg.py` accept/reject errors.

Accepted an empty subject; rejected `fix(F4c-T1)` because the retrofit letter was placed after
`-T` rather than after the feature number; rejected `Revert "..."` as generated by `git
revert`. **Fixed, all three**, verified across ten cases.

Video-codec and Office-suite version tokens of the shape *letter-then-digits* are an
**accepted false positive, with the reason recorded in the source** — nothing in a subject
line distinguishes them from a real citation, and the case is contrived for a mesh client.
Writing the Office one out longhand in this paragraph promptly failed the upstream citation
check, which resolves bare IDs as well as backticked ones. The false positive demonstrating
itself inside the finding that documents it is the best argument available that it is real
and that living with it is the right call.

### 9. The pre-commit ran the suite twice and rebuilt the wheel three times.

`count_assertions.py --check` runs the suite itself and fails loudly when red, fully subsuming
the separate `pytest` line. **Fixed:** the duplicate run is gone, with a comment saying why the
declared `run` capability still exists.

### 10. Two weak spots in the suite.

`test_fits_at_the_boundary` used `"a" * limit` — pure ASCII, in the one test where the
byte/character distinction is the point, in a file whose docstring claims every encoding
fixture is multi-byte. **Fixed** to pad-plus-emoji.

**Not fixed, recorded instead:** 22 of the assertions come from one loop, so the floor is
satisfiable by lengthening a fixture string — *"assertions executed" is the right metric for a
suite that stopped running and a weak metric for a suite that shrank.* Carried as `RR11`.

## What the reviewer confirmed as sound

Stated so it is not re-litigated: the mutations genuinely kill on the shipped file and restore
it under normal exit and Ctrl-C; `count` exactly matched a hand count of 38; the floor
correctly refused a deleted test; `check_secrets` scans staged content rather than the working
tree and caught the service-account key; the suite passes with the radio powered off, and
nothing under `tests/` imports a transport.
