## Why first

`D21` moves everything to Swift. Every later Swift unit needs the same five things `C1` built
in Python — run, count, floor, mutate, pre-commit — or its claims are assertions. This unit
builds them and retires the Python harness. It delivers nothing user-visible.

## Decisions this plan asks you to ratify at the gate

Agent-decided from evidence; each one can be overturned.

| ID | Decision | Evidence |
|---|---|---|
| `D25` | **One Swift package at the repo root.** Swift 6 language mode, so the compiler rejects data races in connection code. Libraries `MeshKitCore` (protocol, connection, no UI) and `MeshKit` (observable state for SwiftUI). The macOS and iOS app targets come at the first feature gate, not here. Platforms: macOS 14, iOS 17 — the first versions with `@Observable`. | `swift --version` → Swift 6.4, Xcode 27.1 |
| `D26` | **Swift Testing (`import Testing`, `#expect`) is the test runner.** Same reason as `D6`: a failing `#expect` prints the values on both sides, so the failure explains itself. | built and ran in the scratchpad spike |
| `D27` | **The count reads code coverage.** Swift Testing reports tests, not checks. Coverage records how many times each `#expect`/`#require` line ran, so loop iterations count and a test that stops early counts less. | spike: 5 checks, hand count 5; the event stream reported 0 |
| `D28` | **Meshtastic protobufs are generated by us from `meshtastic/protobufs` at tag `v2.7.26`** (the radio's firmware), and the generated Swift is committed. Adds `apple/swift-protobuf` (Apache-2.0) as the one dependency. Regenerating needs `protoc` and `protoc-gen-swift` via Homebrew; building does not. The `.proto` files are GPL-3.0, which makes `D18` effectively required. | `gh api repos/meshtastic/protobufs` → GPL-3.0, tag `v2.7.26` exists; `which protoc` → not found |

**Tooling is Swift too.** "Everything" in `D21` covers the harness scripts. They become one
executable target, `harness`, with subcommands — `swift run harness count`. It is never
linked into an app.
